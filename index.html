Sample Payload

{
  "count": 10,
  "schema": {
    "order_id": "uuid",
    "items": {
      "type": "array",
      "minItems": 1,
      "maxItems": 3,
      "schema": {
        "price": {"type": "decimal", "min": 10, "max": 200, "decimals": 2},
        "quantity": {"type": "number", "min": 1, "max": 5}
      }
    }
  },
  "computedFields": {
    "subtotal": "sum(items[].price * items[].quantity)",
    "tax": "subtotal * 0.08",
    "total": "subtotal + tax"
  }
}

What You Can Achieve

Designed for production-grade testing pipelines, not one-off mock data scripts.

Schema-Driven Generation

Generate nested arrays, bounded numeric ranges, decimals with precision, and canonical identity/contact fields.

Business Logic Coverage

Apply arithmetic, conditional, and aggregation expressions to mimic real checkout and pricing logic.

QA Edge Case Injection

Blend normal and edge records in one dataset to validate guardrails and runtime behavior under extremes.

How It Works

01

Define the schema

Describe each field as a simple faker type or a complex typed definition with constraints.

02

Add computed fields

Layer in business-rule expressions for taxes, discounts, shipping, and order-level rollups.

03

Enable QA mode

Set edge case ratio and include types to stress your APIs with boundary-aware payloads.

04

Generate and validate

Consume JSON output with embedded metadata so your pipeline can separate normal and edge records.

Current Limitations

Transparent boundaries help teams adopt confidently and prioritize roadmap work.

Expression & Modeling Constraints

  • No nested expression language or advanced logical operators.
  • No relational cross-dataset constraints (foreign key style links).
  • No custom plugin hooks for generator extensions.

Platform Constraints

  • JSON output only; no direct database write mode.
  • Single locale default (en_US).
  • Synchronous request-response generation model.
